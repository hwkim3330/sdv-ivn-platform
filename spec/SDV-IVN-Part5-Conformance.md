# SDV-IVN Part 5 — 상호운용성 및 적합성 시험

버전 0.1.0 · 2026-09 · 상태: 초안
구현: `tests/`

## 1. 세 층위

| 층위 | 묻는 것 | 장비 |
|---|---|---|
| A. 프로파일 적합성 | 구현이 Part 3·4 의 규칙대로 사상하는가 | 불필요 |
| B. 응용 적합성 | 레퍼런스 애플리케이션의 실제 트래픽이 프로파일에 들어가는가 | 불필요 |

## 2. 층위 A — 프로파일 적합성 (`tests/unit`, 33건)

두 번째 구현이 통과해야 할 항목이다. 이 저장소의 구현 내부가 아니라
**프로파일의 약속**을 검사한다.

| 항목 | 검사 |
|---|---|
| 등급 | 다섯 개, ID 고정, PCP 중복 없음, 긴급도 순 |
| KPI | SAFETY_CRITICAL·REDUNDANT_SAFETY 가 5 ms / 2.5 ms 를 갖는가 |
| 프레이밍 | 대역이 페이로드보다 큰가, MTU 초과가 조각당 오버헤드를 내는가, 최소 프레임을 지키는가 |
| DDS | 마감이 주기로 조여지는가, 안전 등급이 RELIABLE·KEEP_LAST 1 인가, REALTIME 이 BEST_EFFORT 인가 |
| 우선순위 | TRANSPORT_PRIORITY 와 PCP 가 같은가 |
| 링크 | T1S 가 센서 페이로드를 거부하는가, TAS 를 strict priority 로 내리는가 |
| 승인 | FRER 대역을 두 번 세는가, 75 % 상한이 걸리는가 |
| TAS | 창 합이 사이클과 같은가, 가드밴드가 있는가, 안 맞으면 실패하는가 |
| CBS | sendSlope 가 음수인가, idleSlope 가 예약 대역인가, 선점이 hiCredit 을 낮추는가 |
| 능력 | 없는 기능을 거부하는가, 미측정을 다르게 거부하는가, 예외가 기능을 실제로 제거하는가 |

## 3. 층위 B — 응용 적합성 (`tests/conformance`, 14건)

레퍼런스 애플리케이션의 트래픽 카탈로그를 프로파일에 넣는다. 토픽이 추가돼
예산이 깨지면 **데모가 아니라 시험이 먼저 깨지는 것**이 목적이다.

| 항목 | 검사 |
|---|---|
| 카탈로그 | 27 토픽 전부 해석되는가, 11개 버킷을 덮는가 |
| 출처 | 가정한 값에 근거가 적혀 있는가 |
| 승인 | 링크별로 전부 승인되는가 |
| 엣지 버스 | 상태·명령만 있는가, 스트림당 1 Mb/s 미만인가, 이중화 스트림이 없는가 |
| 스케줄 | 링크별 게이트 목록이 만들어지는가 |
| 벤치 | LAN9692 가 이중화 스트림을 거부하는가, 기록된 예외로 돌아가는가 |

## 4. 층위 C — 성능 적합성 (벤치 필요)

### 4.1 측정 대상

| 지표 | 단위 | 목표 | 대상 등급 |
|---|---|---|---|
| Edge → HPC 지연 | µs | ≤ 5,000 | SDV_QOS_3, 4 |
| 지터 | µs | ≤ 2,500 | SDV_QOS_3, 4 |
| 유실률 | % | 0 | SDV_QOS_3, 4 |
| Deadline miss | 건 | 0 | SDV_QOS_3, 4 |
| Liveliness lost | 건 | 0 | SDV_QOS_3, 4 |
| 처리량 | Mb/s | 프로파일 예약치 이상 | 전 등급 |
| 디스커버리 시간 | ms | — | 참고 |

지연은 **p50 이 아니라 p99 와 최댓값**으로 판정한다. 안전 등급에서 중앙값은
의미가 없다.

### 4.2 측정 조건 (필수)

**부하가 걸린 망에서 잰다.** 한가한 링크의 지터는 이 아키텍처가 있든 없든
좋으므로, 그 조건의 측정은 아무것도 증명하지 못한다.

| 시나리오 | 배경 부하 | 관측 대상 |
|---|---|---|
| S1 정상 | 프로파일 전체 | 전 KPI 스트림 |
| S2 경합 | S1 + BEST_EFFORT 포화 | 안전 등급이 영향받지 않는가 |
| S3 대용량 | S1 + 지도 전송 | 마감 유지 |
| S4 링크 단절 | S1, 한 경로 물리 단절 | FRER 무결절 여부, 복구 시간 |
| S5 FRER on/off | S1 | 켰을 때와 껐을 때의 차이 |
| S6 스위치 고장 | S1, 한 스위치 전원 차단 | 재구성 시간 |
| S7 T1S 노드 고장 | 엣지 세그먼트 | 나머지 노드 영향 |

### 4.3 대조군 (필수)

TSN 설정을 **끈 상태**를 같이 잰다. TAS/CBS/우선순위 없이 같은 부하를 흘린
결과가 없으면, 측정된 지터가 좋은 것인지 원래 그런 것인지 알 수 없다.

| 설정 | 의미 |
|---|---|
| baseline | 우선순위·셰이퍼 없음, 전부 BE |
| pcp-only | 우선순위만 |
| full | 프로파일 전체 (TAS + CBS + 선점) |

### 4.4 PCP 7 항목

Part 3 §3 이 남긴 질문이다.

| 설정 | 측정 |
|---|---|
| `allow_pcp7_for_applications: true` | 부하 중 gPTP 오프셋 분포 |
| `allow_pcp7_for_applications: false` | 같은 부하, 같은 측정 |

애플리케이션이 PCP 7 을 쓸 때 시간 동기가 얼마나 나빠지는지가 답이다.
나빠지지 않으면 현재 설정을 유지하고, 나빠지면 프로파일을 고친다.

## 5. 상호운용성

| 항목 | 내용 |
|---|---|
| DDS 구현 간 | Fast DDS 발행 ↔ Cyclone 구독, 양방향 |
| 장비 간 | LAN9692 ↔ Kontron D10 을 거쳐 같은 등급이 유지되는가 |
| 매체 간 | Multi-GigE ↔ 10BASE-T1S 경계에서 우선순위가 보존되는가 |
| 구현 간 | 두 번째 매퍼 구현이 같은 입력에 같은 YANG 을 내는가 |

## 6. 보고 규칙 (필수)

- 측정하지 않은 항목은 `—` 로 적는다. `0` 으로 적지 않는다.
- 기록된 예외로 강등된 스트림은 보고서에 강등 사실과 사유가 함께 나온다.
- 대조군 없는 성능 수치는 보고하지 않는다.
- 실패한 시나리오는 성공한 것과 같은 자리에 적는다.
